## Part 1: the daily run on the new pipeline

1. **`outreach_due.py`: keep the stock ahead of the cap.** It prints how many new first emails to prepare
   today, so that ready plus needs_approval first emails cover the next 2 send days' cap (from
   `send.py daily_cap` and the ramp), minus follow-ups and chain emails due. It also prints `CALLS` from
   `calls.py due`, and a weekly `HIGH-VALUE` line (Mondays) with the number of new signal leads above the
   threshold. Add self-test checks for the stock maths.
2. **`docs/runbook.md` "The daily run"**, rewritten for the new steps:
   - status
   - sync
   - replies drafted into `drafts/reply-<org>.txt`
   - due
   - follow-ups (`followups.py prepare`)
   - new organisations: `enrich.py batch` → score gate → researcher agents (Haiku) on digests, 5-8 per
     call → `render_draft.py` → lint → one checker pass → `gmail_draft.py draft` → `send.py ready`
   - Mondays: the high-value track's Part 1 and 2 for up to 5 new leads (per the S4 prompt)
   - report

   **Budget per run:** at most 60 organisations researched. Write each run's subagent token total into
   `state/log.md`.
3. **`tools/daily_run.ps1`.**
   - The prompt stays free of double quotes, and is updated to follow the new runbook.
   - Main session `--model sonnet`; the agents it starts use Haiku.
   - The allowed tools still exclude `send.py run`, `send.py approve` and `git push`; add
     `Bash(python tools/sources/*)` if needed.
   - After the send loop, the mailed report includes:
     - the `send.py approvals` list, and the path of `approvals.html` (regenerated each run)
     - today's `calls.py due`
     - replies that need Manuel
     - stock in days
4. **Complaint stop.** In `gmail_draft.py sync`, a human reply that complains (spam, klacht, AVG/GDPR,
   "how did you get", "hoe komt u aan", "wie kommen Sie an") writes `state/STOP` with the thread id and
   puts it first in the report. It is still recorded as an opt-out. Add self-test checks.
5. **Postmaster and DMARC (D12).** Draft the request to the DNS owner into `drafts/dns-request.txt`: a
   Postmaster Tools TXT record for 180dc.org, and a `rua=` address on the existing `p=none` DMARC record.
   You don't send it. If D12 names a person, address it to them.
6. **January wave (D10).** If yes, change `limits.yaml` so sending also runs 5-16 Jan. Follow-ups pending
   from 15-22 Dec go first, and first emails go on 5-9 Jan only. Self-test check. If blank, change nothing.
7. **Second inbox (D11).** If a person and address are named, build sender-per-touch:
   - `tenant.yaml` `senders:` list, one OAuth token per sender in `private/`, the touch records its sender
   - per-sender ramp and cap, sync reads every inbox, footer and signature per sender
   - self-test checks for each

   It stays switched off until Manuel sets the sender's start date after a clean Postmaster week. If
   blank, write the design only into `docs/second-inbox.md`.
