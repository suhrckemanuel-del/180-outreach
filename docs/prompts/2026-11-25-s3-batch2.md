## Part 1: researcher reads the digest, code writes the email

1. **`researcher.md`.** The input becomes the digest file from `state/enrich/<domain>.md` (5-8
   organisations per call). The researcher gets one WebFetch, and only when the digest is ambiguous on the
   workflow. Add these card fields, each with its URL:
   - `FACT:` one English sentence, their workflow in their words, no Dutch words
   - `GUESS:` one sentence on the sector workflow, worded as a guess
   - `WORKFLOWS:` w1 | w2 (short English noun phrases for `add-touch --workflows`)
   - `TOPIC:` 2-5 words for the subject
   - `CONTACT:` the address to use, its page, and the person's name only if printed beside it, else the
     director from PEOPLE for the subject
   - `PHONE:` the printed number and its page (for S4's calls)

   Keep the card under ~180 words. The verdict rules stay the same.
2. **`tools/render_draft.py --touch ID`** fills the arm's template from the card and the ledger, with no
   model:
   - Greeting: the full name, or "<org> team". Never Mr/Ms, so no gender is guessed.
   - Subject: per the template, with "For <name>:" when writing to an inbox.
   - Tags: `[src:]` after FACT, `[claim:]` after every sentence about us.
   - Track record: TR-REVIEWER by default. TR-PROPERTY only when the result stays at 125 words or fewer.
     TR-EVIDENCE only if D9 is OK.
   - Use BR-PROJECT-SHAPE only if D13 added it to the ledger. If D13 gives the wording, add the claim to
     `ledger.yaml` first with `usable: true`.
   - Lint inside; if the draft runs over 125 words, drop the GUESS sentence and say so.
   - Add self-test checks: a fixture card renders to a lint-clean draft for each arm, no gendered title,
     no Dutch words from a stop list.

## Part 2: batch 2

3. **Use a workflow** for research: researcher agents (Haiku, per `.claude/agents/researcher.md`), 5-8

5. One checker pass for all drafts (cards, drafts, `ledger.yaml`). If there are more than 15 drafts, run
   it as a workflow of checker agents (Haiku, 15 drafts each, in parallel), still one pass. Fix or drop
   every FAIL and say which. Read 5 random clean drafts yourself, and fix any that read generic.
6. `gmail_draft.py draft --touch <id>` then `send.py ready --touch <id>` for each. Expect
   `needs_approval` until 30 first emails have been sent. Then `send.py approvals --html`.
