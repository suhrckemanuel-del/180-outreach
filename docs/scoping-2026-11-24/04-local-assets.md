Scoped 2026-11-24. Read-only inventory of C:\Users\User\Desktop. For each folder I read the README/CLAUDE.md/top-level scripts and file listings only. I did not open data dumps, state files, `private/`, `.env` or token files (several folders contain a `.env`; I did not read them). Everything below comes from file names, docs and module headers. I did not run any test suite, so "tests exist" means test files exist, not that they pass.

Effort scale: S = under half a day, M = 1-2 days, L = a week or more.

## Gaps in the kit versus these assets

- The kit's `tools/firm_contacts.py` already fetches own-site pages, caches for 7 days, respects robots, reads PDFs and builds a people digest. It does not decode `[at]`-style addresses, read schema.org JSON-LD, drop role boxes, reject third-party-domain addresses, or check MX. All of those exist in `BDR-pipeline/app/services/email_finder.py` (own code) and in the AMSA `contact_lookup` package (flagged).
- No local asset covers bounce or reply parsing beyond `gmail_draft.py sync`, SPF/DKIM/DMARC checks, a shared multi-user approval UI, or a Maps-compliant lead list. Those need new code or an outside tool.
- Tests: BDR-pipeline (14 test files), the AMSA `contact_lookup` (6 plus places/render/score) and `outreach-kit` (one) have tests. The 180DC kit has `tools/selftest.py` only.
